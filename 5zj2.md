# Upgrade cross-origin delegation from a hint to a signed endorsement (this.i @bio6glms, @uymk2j6q). host-meta-v2.json currently declares 'strength': 'hint' with a delegationNote saying it conveys no trust -- accurate today, and deliberately weaker than what a consumer would find useful. The strong form has the apex vouch for schema.bakobo.com, so that trusting bakobo.com extends to what it names. BLOCKED, and not on effort: an endorsement is worth exactly what its signature is worth, and Bakobo has incepted no organisational AID (@7vpcnhmt), so an unsigned assertion that one origin vouches for another can be forged by anyone able to replace the file -- the same unauthenticated-directory problem @uymk2j6q names as GLEIF's conspicuous gap. So this is downstream of inception, and of the catalog-signing work in ~3kqd part 1, which shares the key and should be built in the same pass. When it happens: keep 'hint' as a valid value rather than replacing it, since some delegations really are only pointers, and the whole point of stating strength is that a reader can tell the two apart. Also revisit @7ufzxzip's prose on the landing page, which is currently the only place the relationship is asserted rather than merely indicated.
