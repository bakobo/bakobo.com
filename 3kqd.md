# Build host-meta-v2.json: the four things GLEIF's discovery mechanism leaves on the table (this.i @uymk2j6q). Approved as a direction on 2026-09-04, unstarted. Ships as a SIBLING file so the GLEIF-conformant surface stays exactly conformant and a consumer can ignore v2 entirely. (1) The catalog is unsigned and carries no $id -- GLEIF's generation 3 dropped the SAID earlier generations had, so a compromised Pages deploy rewrites which AIDs a stranger believes are ours and nothing detects it. From an organisation whose whole technology is self-certifying identifiers this is the conspicuous gap, and it is the one worth building first. Blocked until Bakobo has an org AID to sign with -- see @7vpcnhmt; nothing has been incepted. (2) 'updated' is a bare date with no semantics, so a cached copy never goes stale on purpose: add validUntil. (3) No cross-origin delegation, which Bakobo needs TODAY -- @7ufzxzip keeps schemas at schema.bakobo.com and the apex has no machine-readable way to say 'that origin, on our authority', only prose. (4) A withdrawn witness just vanishes, so a client holding a cached entry cannot distinguish retired from unreachable: tombstones. Also use a stable shared rel rather than GLEIF's origin-scoped {host}/rels/oobi, which makes a generic cross-publisher client impossible. Order matters: machine artifact first, prose second -- GLEIF wrote STRUCTURE.md v1.0.0 as a real spec and deleted it nine months later when the implementation moved (see infra docs/gleif-well-known.md). Write-up goes in bakobo/schema, not a new repo.
